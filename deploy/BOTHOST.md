# Развёртывание DETAIL LAB на Bothost (bothost.ru)

Bothost — управляемый хостинг ботов: серверов и SSH нет, код берётся из Git или zip-архива, секреты
задаются переменными окружения в панели. Подходит для этого бота; для варианта «свой VPS» см. `DEPLOY.md`.

> Сверено с документацией Bothost на дату подготовки. Названия кнопок в панели могут слегка отличаться.

## Что важно знать заранее
- **Нужен тариф «Базовый» — 99 ₽/мес** (годовой 1010 ₽): на бесплатном нет переменных окружения и база
  стирается при перезапуске, к тому же создание ботов там сейчас недоступно. На Базовом до 5 ботов.
- **База хранится в `/app/data`** — эта папка не затрагивается обновлениями кода и перезапусками.
  Бот по умолчанию пишет в `/app/data/detail_lab.db`, но мы всё равно задаём `DATABASE_PATH`.
- **Локация:** Россия (Москва) или Нидерланды (на платных тарифах). Москва сохраняет данные клиентов в РФ
  (152-ФЗ). Если в Москве бот не будет достучаться до Telegram (ошибки сети в логах), пересоздайте бота с Нидерландами.
- Токен платформа подставляет сама в `BOT_TOKEN` из поля формы.

## Шаги
1. **Новый токен.** Прежний токен публиковался в чате. В @BotFather: `/revoke` → выберите бота → скопируйте новый токен.
   Бот на вашем компьютере после этого перестанет работать — это нормально (его и нужно остановить: `pkill -f bot.py`).
2. **Тариф:** https://bothost.ru/pricing.php → «Перейти на Базовый» → оплата.
3. **Создание бота:** https://bothost.ru/create-bot.php
   | Поле | Значение |
   |---|---|
   | Название бота | DETAIL LAB |
   | Платформа | Telegram |
   | Язык разработки | Python |
   | Версия Python | **3.12** |
   | Bot Token | новый токен из шага 1 |
   | Локация развертывания | Россия (Москва) |
   | Git URL репозитория | `https://github.com/khadiev17timur-tech/detail_lab_bot` (репозиторий приватный, см. ниже) |
   | Ветка | `main` |
   | Дополнительные настройки → Главный файл | `bot.py` |

   **Переменные окружения** (раздел в форме):
   ```
   ADMIN_IDS=<ваш числовой Telegram ID, узнать у @userinfobot>
   MANAGER_USERNAME=<тег менеджера без @>
   DATABASE_PATH=/app/data/detail_lab.db
   ```
   При необходимости: `TIMEZONE`, `STUDIO_PHONE`, `STUDIO_ADDRESS`, `DEMO_MODE=false` (см. `.env.example`).
4. **Приватный репозиторий.** Вариант А — подключить GitHub по инструкции Bothost («Подключение приватного
   репозитория»: токен или deploy key). Вариант Б (проще) — **загрузить архив**: на компьютере
   `./deploy/make_archive.sh` создаёт `~/Downloads/detail_lab_bot.zip` без секретов и базы; его загружают
   в мастере «Загрузка бота из архива».
5. **Проверка:** откройте «Логи работы» — должно быть `Бот @... запущен`. Напишите боту `/start`, оформите
   тестовую заявку, проверьте `/admin`.

## Резервные копии
Помимо «авто-бэкапов» платформы бот сам делает копию базы **каждую ночь в 03:30** (время студии):
файл `detail_lab-ГГГГ-ММ-ДД.db.gz` в `/app/data/backups/` (хранятся последние 7) и **присылает его администраторам в Telegram** —
так копия лежит вне хостинга. Вручную: команда `/backup` или кнопка «💾 Бэкап базы» в `/admin`.
Настройки: `AUTO_BACKUP`, `BACKUP_SEND_TO_ADMINS`, `BACKUP_KEEP`.

> В копии — данные клиентов. Не пересылайте файл посторонним.

**Восстановление:** распакуйте `.db.gz` (`gunzip`), остановите бота в панели, загрузите файл через файловый менеджер
в `data/` под именем `detail_lab.db` (старый переименуйте, не удаляя), запустите бота.

## Обновление кода
- Из Git: в панели «Обновить из Git» (или автообновление при `git push`, если доступно на тарифе).
- Из архива: соберите новый архив и загрузите на карточке бота — токен, переменные и `data/` сохраняются.

## Если что-то не работает
| Симптом в логах | Причина и решение |
|---|---|
| `Conflict: terminated by other getUpdates` | тот же токен запущен ещё где-то (на вашем Mac) → `pkill -f bot.py`, перезапустить на Bothost |
| `Telegram отклонил токен (Unauthorized)` | токен неверный или отозван → вставить актуальный в настройках бота |
| `Ошибка конфигурации: ...` | неверная переменная (текст ошибки подскажет, какая) |
| `TelegramNetworkError` / таймауты долго | с выбранной локации нет связи с Telegram → пересоздать бота с другой локацией |
| `ModuleNotFoundError` | выбрана версия Python < 3.11 или неполный архив → Python 3.12, новый деплой |
| База «пропала» после обновления | `DATABASE_PATH` указывает вне `/app/data` → исправить и восстановить из копии |
| `restarting` | смотрите первую ошибку в «Логах работы» |
