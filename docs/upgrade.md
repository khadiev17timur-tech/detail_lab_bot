# Безопасное обновление боевого бота до версии 2

> Состояние на 2026-10-13: боевой бот работает на Bothost из ветки `main` (схема БД v1, метка `v1-stable`).
> Версия 2 лежит в ветке `feature/v2-retention`. **Ничего из описанного ниже ещё не выполнялось** — без вашего «да» `main` и Bothost не меняются.

## Что изменится при обновлении
- Схема SQLite обновится v1 → v2 **автоматически при первом старте** (пересборка таблицы `bookings` ради нового статуса «отменена»,
  новые таблицы: автомобили, задания, отзывы, скидки, закрытые даты, согласие на предложения).
- Существующие заявки, клиенты и история статусов сохраняются. Старые заявки с «любым временем» остаются читаемыми и **не блокируют календарь**.
- Для старых заявок автоматически создаются автомобили клиентов («Мой автомобиль» сразу с историей).
- Незавершённые черновики записи (в памяти бота) при перезапуске, как и раньше, сбрасываются.

## Подготовка (без риска, можно сделать заранее)
1. Убедитесь, что текущий бот отвечает, и получите **ручную копию базы**: администратору — команда `/backup` (бот пришлёт файл `.db.gz`).
   Сохраните его у себя. Дополнительно можно скачать папку `data` из файлового менеджера Bothost («Файлы»).
2. Проверьте, что `v1-stable` существует: `git tag -l` (метка уже создана на последнем рабочем коммите `main`).
3. (Необязательно) Добавьте переменные в панели Bothost → бот → «Переменные»:
   `REVIEW_URL` (ссылка на страницу отзывов), `STUDIO_POSTS` (сколько авто студия принимает одновременно, по умолчанию 2),
   `REMINDER_HOURS` (например `24,2`). Без них работают значения по умолчанию.

## Выкладка (только после вашего разрешения)
1. Слить ветку в `main` (Pull Request на GitHub или `git merge`), убедиться, что тесты зелёные.
2. В панели Bothost нажать **«Обновить из Git»** (бот пересоберётся 2–5 минут).
3. В «Логах работы» должны появиться строки:
   - `Перед миграцией схемы v1→v2 сохранена копия базы: …/backups/pre-migration-v1-to-v2-…db`
   - `Схема базы обновлена до версии 2`
   - `Бот @… запущен` и `Start polling`
4. Проверьте по чек-листу (5 минут, в Telegram):
   - `/start` — меню из 9 кнопок, есть «Мой кабинет».
   - «Записаться» → услуга → авто → дата → **время показывается только свободное** → заявка → приходит админу.
   - «Мой кабинет → Мои записи»: запись видна, «Перенести» и «Отменить» работают, админ получает уведомления.
   - Админ: `/admin` → «Расписание», «Отзывы», «Аналитика», «Скидки» открываются; старые заявки на месте (`Все заявки`).
   - `/backup` присылает файл.

## Откат (если что-то пошло не так)
Откат кода **без** возврата базы не работает: v1-код не умеет читать статус «отменена» и новые поля. Порядок:
1. В Bothost остановить бота.
2. В файловом менеджере: переименовать `data/detail_lab.db` в `data/detail_lab.v2-broken.db` (не удалять), скопировать
   `data/backups/pre-migration-v1-to-v2-….db` в `data/detail_lab.db`.
3. В настройках бота выбрать ветку/метку **`v1-stable`** (или откатить `main` на неё) → «Обновить из Git».
4. Запустить бота и проверить `/admin`.
Заявки, созданные уже после обновления, в откатной копии отсутствуют — поэтому перед выкладкой стоит предупредить менеджера
и не откладывать решение об откате.

## Риски и как они снижены
| Риск | Что сделано |
|---|---|
| Сбой в середине миграции | миграция — одна транзакция (всё или ничего), перед ней — автоматическая копия, после — проверка внешних ключей; сбой возвращает базу в v1 (тест) |
| Потеря заявок | старые данные копируются как есть; тест на реальной v1-базе проверяет заявки, историю статусов, телефоны, комментарии |
| Лавина сообщений после простоя | напоминания, опоздавшие больше чем на `reminder_late_grace_min` (30 мин), пропускаются; одна отправка за раз, лимит на проход |
| Дубли напоминаний/отзывов | задание уникально (заявка + тип), берётся атомарно; прерванные падением помечаются «не доставлено», а не отправляются повторно |
| Двойное бронирование | занятость проверяется внутри транзакции; тест на 12 параллельных попыток на последний пост |
| Реклама без согласия | предложения и рекомендации по уходу — только с согласием; отключение: «Мой кабинет → Уведомления» или `/stop` |
