# DETAIL LAB — демо-бот детейлинг-студии (Telegram)

Готовый к запуску Telegram-бот для детейлинг-студии: каталог услуг, прайс, калькулятор стоимости,
**запись на свободное время**, личный кабинет клиента, напоминания, отзывы, «Мой автомобиль» с историей ухода,
персональные скидки, админ-панель, портфолио, FAQ и контакты.
Задуман как **демонстрационный продукт**: все данные студии вымышленные и помечены как демо,
их легко заменить под реального клиента (см. раздел 9).

## Что умеет бот (версия 2)

| Для клиента | Для студии |
|---|---|
| Запись: услуга → авто → **только свободное время** → контакты; время резервируется за клиентом | Календарь: длительность услуг, число постов, рабочие часы, **защита от двойного бронирования** |
| **Мой кабинет**: мои записи, «Приду», **перенос и отмена** без звонка | Уведомления о новых заявках, переносах и отменах; кнопки «принять / отклонить» |
| **Напоминания** о визите (по умолчанию за 24 и 2 часа) | Расписание на день, **закрытые даты**, аналитика за 30 дней |
| **Отзыв** после визита: оценка 1–5 + комментарий | Сигнал о **плохой оценке**, список отзывов, единая ссылка на публичную площадку |
| **Мой автомобиль**: подтверждённая история и рекомендации по уходу (ориентиры студии) | Правила рекомендаций редактируются в `content/care.py` |
| Персональные **скидки** (за N-й визит, «давно не были»); согласие на предложения, отказ — `/stop` | **Мастер правил скидок** в админке: процент/сумма, срок, условие; учёт и защита от повторного применения |

Подробности и результаты проверок: [`docs/audit.md`](docs/audit.md). Безопасное обновление боевого бота: [`docs/upgrade.md`](docs/upgrade.md).

Стек: Python 3.11+, aiogram 3.x, SQLite (aiosqlite), python-dotenv, FSM aiogram, logging.
Платных API и внешних сервисов нет.

## 1. Требования

- **Python 3.11 или новее** (проверялось на 3.12).
- Аккаунт Telegram.

```bash
python3 --version
```

## 2. Виртуальное окружение

```bash
cd detail_lab_bot
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
```

## 3. Установка зависимостей

```bash
pip install -r requirements.txt          # только для запуска
pip install -r requirements-dev.txt      # + pytest, чтобы гонять тесты
```

## 4. Создание бота в BotFather

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) (официальный бот, с синей галочкой).
2. Отправьте `/newbot`.
3. Введите **название** (например, `DETAIL LAB Demo`) и **username**, оканчивающийся на `bot`
   (например, `detail_lab_demo_bot`).
4. BotFather пришлёт **токен** вида `123456789:AA...`. Это пароль к боту — никому его не показывайте
   и не публикуйте. Если токен утёк — отзовите его в BotFather: `/revoke`.

## 5. Заполнение `.env`

```bash
cp .env.example .env
```

Откройте `.env` и вставьте токен:

```
BOT_TOKEN=123456789:AA...ваш_токен
ADMIN_IDS=111111111
```

Файл `.env` добавлен в `.gitignore` и в репозиторий не попадёт.

## 6. Как узнать Telegram ID администратора

Напишите боту [@userinfobot](https://t.me/userinfobot) — он ответит числом `Id`.
Впишите его в `ADMIN_IDS`. Администраторов может быть несколько, через запятую: `ADMIN_IDS=111111111,222222222`.

> Администратору нужно один раз нажать **Start** у вашего бота — иначе Telegram не даст боту
> написать ему первым, и уведомления о заявках не придут.

## 7. Запуск

```bash
python bot.py --check    # проверка конфигурации, базы и обработчиков (без подключения к Telegram)
python bot.py            # запуск бота (остановить: Ctrl+C)
```

В логе появится `Бот @... запущен`. Откройте бота в Telegram и отправьте `/start`.
Если токен неверный, бот сообщит об этом понятной ошибкой, а сам токен в журнал не попадает.

## 8. Как проверить основные сценарии

1. `/start` — приветствие и меню из 9 кнопок. Пройдите по каждой кнопке.
2. **Услуги → любая услуга**: описание, преимущества, цена «от», срок, «Записаться на услугу», «К каталогу».
3. **Цены**: прайс по категориям и предупреждение о ценах; из прайса откройте услугу.
4. **Рассчитать стоимость**: услуга → класс авто → доп. работы → расчёт → «Оставить заявку» /
   «Рассчитать заново» / «В меню».
5. **Записаться**: услуга → авто → класс → дата → время → имя → телефон (кнопкой или вручную) →
   комментарий (можно пропустить) → проверка → галочка согласия → «Отправить заявку».
   Попробуйте: «Назад», `/cancel`, неверный телефон (`123`), прошедшую дату (`01.01.2020`), двойное нажатие на «Отправить».
6. Администратор получит сообщение с кнопками **✅ Принять в работу / ❌ Отклонить / 📋 Подробнее**.
   Нажмите кнопку — клиент получит уведомление о новом статусе.
7. `/admin` — панель: новые заявки, последние 10, все (с листанием), по статусам, статистика, выгрузка CSV,
   смена статуса в карточке заявки. С чужого аккаунта `/admin` отвечает отказом.
8. **Портфолио**, **Частые вопросы**, **Контакты**, **Связаться с менеджером**.
9. **Мой кабинет → Мои записи**: откройте запись, перенесите её на другое время, затем отмените. Админ получит уведомления,
   освободившееся время снова доступно для записи.
10. Админ: «Принять в работу» → «Завершена». Клиенту придёт запрос оценки (через `review_delay_hours`, по умолчанию 3 часа),
    после оценки 1–3 админу придёт сигнал. **Мой кабинет → Мой автомобиль** покажет историю и рекомендации.
11. `/admin` → «Скидки» → «Новое правило»: создайте скидку «после 1-го визита», завершите визит — клиент получит купон
    (сообщение — только если он включил предложения в «Мой кабинет → Уведомления»).

Автоматические тесты (не требуют токена и сети):

```bash
python -m pytest -q
```

## 9. Где менять услуги, цены, контакты и настройки

| Что                                         | Где                                                                     |
|---------------------------------------------|-------------------------------------------------------------------------|
| Услуги, цены «от», сроки, преимущества      | `content/catalog.py` → `SERVICES`                                       |
| Коэффициенты классов авто                   | `content/catalog.py` → `CAR_CLASSES` (`coef_pct`: 100 = ×1,00)          |
| Дополнительные работы и их цены             | `content/catalog.py` → `ADDONS` и `addon_ids` у услуги                  |
| Название, слоган, адрес, график, телефон    | `content/studio.py` или переменные в `.env`                             |
| Ссылка на менеджера, карту, сайт            | `.env`: `MANAGER_USERNAME`, `MAP_URL`, `WEBSITE_URL` (пусто → не показываются) |
| Часы работы, шаг сетки, посты, выходные      | `content/studio.py` → `open_time`, `close_time`, `slot_step_min`, `posts` (или `.env` `STUDIO_POSTS`), `closed_weekdays` |
| Длительность услуг и занятость поста         | `content/catalog.py` → `duration_min`, `days` у услуги                  |
| Интервалы напоминаний                       | `.env`: `REMINDER_HOURS=24,2` (часы до визита)                          |
| Отзывы: задержка, порог «плохой» оценки, ссылка | `content/studio.py` → `review_delay_hours`, `review_low_rating`; `.env`: `REVIEW_URL` |
| Правила рекомендаций по уходу               | `content/care.py`                                                       |
| Закрытые даты, правила скидок               | в боте: `/admin` → «Закрытые даты», «Скидки»                            |
| FAQ                                         | `content/faq.py`                                                        |
| Карточки портфолио                          | `content/portfolio.py`; фото — в `assets/portfolio/` (см. там README)   |
| Текст согласия на обработку данных          | `content/policy.py`                                                     |
| Отключить пометки «демо»                    | `.env`: `DEMO_MODE=false`                                               |

Каталог, прайс-лист, калькулятор и заявки берут цены из **одного** источника — `content/catalog.py`.

## 10. База данных

SQLite-файл `data/detail_lab.db` (путь меняется через `DATABASE_PATH`). Таблицы создаются при запуске.

- `users` — кто писал боту (Telegram ID, username, имя, первый/последний визит).
- `bookings` — заявки: номер, услуга (название сохраняется на момент заявки), авто, класс, желаемые
  дата/время, имя, телефон, комментарий, предварительная стоимость, статус, согласие и его время,
  даты создания и обновления. Уникальный `draft_id` защищает от дублей при повторной отправке.
- `booking_status_log` — история смены статусов (кто и когда).
- `cars` — автомобили клиентов (создаются при первой записи, дубли по названию объединяются).
- `jobs` — очередь напоминаний, запросов отзыва и рекомендаций: переживает перезапуск, одно задание на заявку и тип.
- `reviews` — оценки и комментарии (одна на визит); `discount_rules` и `vouchers` — правила и выданные скидки;
  `schedule_blocks` — закрытые даты.

Статусы: `new` (новая), `in_work` (в работе), `accepted` (принята), `rejected` (отклонена студией), `done` (завершена),
`cancelled` (отменена клиентом). Время занято, пока запись в статусах `new`, `in_work`, `accepted`.

**Миграции.** Версия схемы хранится в `PRAGMA user_version` (сейчас 2). При старте бот сам обновляет старую базу;
перед миграцией существующей базы он кладёт копию в `backups/pre-migration-*.db`. Миграция выполняется одной транзакцией
(при сбое база остаётся прежней версии). База из более новой версии бота не открывается — защита от порчи при откате кода.
Посмотреть данные: `sqlite3 data/detail_lab.db "SELECT id, status, name, phone FROM bookings;"` или любой SQLite-клиент.
Резервная копия — просто копия файла `data/detail_lab.db` (остановите бота или используйте `sqlite3 ... ".backup"`).

> Незавершённые черновики заявок хранятся в памяти и при перезапуске бота сбрасываются; отправленные
> заявки в SQLite сохраняются.

## 12. Ограничения демо и шаги перед реальным использованием

Ограничения:
- Заявка — это **предварительное резервирование**: окончательно запись подтверждает менеджер. Расписание ведётся внутри бота
  (посты, часы работы, закрытые даты), внешний календарь не подключён; время, занятое «вручную» вне бота, нужно закрывать в админке.
- Один общий счётчик постов (`STUDIO_POSTS`); многодневные услуги занимают пост целыми днями.
- Напоминания идут по заявкам в статусах «в работе»/«принята».
- Цены, услуги, контакты, FAQ, правила ухода и тексты согласий — демонстрационные.
- Незавершённые черновики записи хранятся в памяти (при перезапуске теряются); отправленные заявки — в SQLite.
- Редактор услуг и цен в админке не реализован — правятся в `content/catalog.py`.

## Дорожная карта (не реализовано в версии 2)
Программа лояльности с баллами и журналом, реферальная программа, портфолио «до/после» с загрузкой из бота,
редактор услуг и цен в админке, раздельные посты по типам работ, внешний календарь. Решение о порядке — по спросу клиентов.

Перед боевым запуском:
1. Заменить данные студии, цены, FAQ, портфолио (и добавить **свои** фото).
2. Заменить текст согласия на политику вашей компании (согласовать с юристом).
3. Указать реальные `MANAGER_USERNAME`, адрес, телефон, `MAP_URL`, `DEMO_MODE=false`.
4. Развернуть на сервере (systemd/Docker), настроить резервное копирование `data/`.
5. Проверить `STUDIO_POSTS`, часы работы и длительность услуг под реальную студию; указать `REVIEW_URL`.
   Текст согласия на рекламные сообщения и политику согласовать с юристом (38-ФЗ, 152-ФЗ).
6. Токен хранить только в `.env`/переменных окружения, при утечке — `/revoke` в BotFather.

## Структура проекта

```
bot.py            точка входа (--check — проверка без запуска)
config.py         чтение .env, валидация
content/          редактируемые данные: каталог, студия, FAQ, портфолио, политика
database/         подключение и схема, модели, запросы (Repository)
services/         расчёт цен, валидация, заявки, админ-логика, CSV, уведомления, тексты
handlers/         меню, услуги, цены, калькулятор, запись, портфолио, FAQ, контакты, админка
keyboards/        клавиатуры и callback-данные
states/           состояния FSM
middlewares/      регистрация пользователей, только личные чаты
utils/            обёртки над Telegram API, логирование, сброс сценариев
assets/portfolio/ фото для портфолио
tests/            автоматические тесты
```
